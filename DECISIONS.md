# Decisions - Kintsugi

## Stack
- Language: Java 17
- Framework: Spring Boot 4.1.1
- Build: Gradle (Groovy DSL), two independent apps (not a multi-module build)
- Database: PostgreSQL (via Docker Compose); never H2, anywhere, including tests
- Config format: application.yaml
- Packaging: Jar (embedded server, not deployed to an external container)

## Repo structure
- `coordinator/` and `worker/` are separate Spring Boot apps, each with
  their own build. They share no code, only the contract below.
- Shared concepts (the Job shape, the REST endpoints) live here, in this
  file, and each app implements its own copy in its own package. A PR
  that changes one side of the contract without updating the other is a
  bug, not a style choice, call it out in review.

## The Job shape
Both apps implement this independently:

| Field            | Type      | Notes                                    |
|-------------------|-----------|-------------------------------------------|
| id                 | UUID      | generated by the coordinator on submit    |
| type               | String    | maps to an executable action              |
| payload            | String    | opaque JSON, coordinator doesn't parse it |
| priority           | int       | higher = more urgent                      |
| status             | enum      | PENDING, RUNNING, SUCCEEDED, FAILED, DEAD |
| retryCount         | int       |                                            |
| maxRetries         | int       |                                            |
| scheduledFor       | Instant?  | nullable                                  |
| nextAttemptAt      | Instant?  | nullable — backoff target (Wave 2)        |
| cronExpression     | String?   | nullable                                  |
| createdAt          | Instant   |                                            |
| assignedWorkerId   | String?   | nullable                                  |
| dependsOn          | List<UUID>| job IDs this job waits on (Wave 4)        |

## REST contract (coordinator exposes, worker calls)

| Method & path                   | Purpose                                   |
|----------------------------------|--------------------------------------------|
| POST /jobs                       | Submit a job → 201 {id}                    |
| POST /jobs/claim                 | {workerId} → 200 {job} \| 204 no job        |
| POST /jobs/{id}/ack-success      | {workerId}                                 |
| POST /jobs/{id}/ack-failure      | {workerId, error}                          |
| POST /workers/{id}/heartbeat     | 200                                        |
| GET  /jobs/{id}                  | Job status, for dashboard/debug            |
| GET  /metrics                    | Queue depth, worker states, throughput     |

## The atomic claim (Wave 3)
Two-step, since @Modifying can't map a RETURNING clause to an entity:

```sql
-- 1. Atomically claim one row
UPDATE jobs
SET status = 'RUNNING', worker_id = :workerId
WHERE id = (
    SELECT id FROM jobs
    WHERE status = 'PENDING' AND (scheduled_for IS NULL OR scheduled_for <= now())
    ORDER BY priority DESC, created_at ASC
    FOR UPDATE SKIP LOCKED
    LIMIT 1
);

-- 2. Fetch the row you just claimed
SELECT * FROM jobs WHERE worker_id = :workerId AND status = 'RUNNING'
ORDER BY created_at DESC LIMIT 1;
```

Wave 1's claim is deliberately a naive read-then-save, this gets swapped
in during Wave 3, on purpose, once the race condition has been observed
and logged in BUGS.md.

## Git conventions
- Branches: `<type>/<short-description>`, e.g. `feature/atomic-claim-skip-locked`
- Types: feature/, fix/, chore/, test/
- Commits: Conventional Commits, `feat: ...`, `fix: ...`, `chore: ...`
- All work merges into `main` via PR, even solo work — CI must pass first
- Delete branches after merge

## Other decisions
- Clock source: `Instant` / UTC everywhere, never local time
- Dependencies (Wave 4): modeled as a real relation, not a JSON blob column
- Config (ports, heartbeat interval, retry base delay, chaos toggles): all
  in application.yaml, never hardcoded
